# Changelog

All notable changes to @reactre/dom, @reactre/core, @reactre/compiler, @reactre/compat, @reactre/full-compat, @reactre/plugin and @reactre/preact are recorded here. The packages are released together, at the same version.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### @reactre/core

- Added: `createRoot(fn)` in `@reactre/core/features/owner`, which runs `fn(dispose)` under a new owner; `dispose` stops the effects and runs the cleanups `fn` made. As in Solid 2.0, a root made inside an owner is disposed with it; one made under `runWithOwner(null, ...)` lives until `dispose`.
- Added: `getOwner()` and `runWithOwner(owner, fn)` in `@reactre/core/features/owner`, to make things later that belong to an owner kept from earlier. `runWithOwner` runs `fn` untracked; with null, what `fn` makes belongs to nothing.
- Added: `onSettled(fn)` in `@reactre/core/features/timing`, Solid 2.0's replacement for `onMount`. `fn` runs once, untracked, under the owner it was called in: at the end of the batch or `flush` it was called in, or else in a microtask, so in a component, once its view is in the page. A function it returns is a cleanup of that owner.
- Added: `flush(fn)` and `flush()` in `@reactre/core/features/timing`, Solid 2.0's replacement for `batch` (which stays). `flush(fn)` runs `fn` and applies its writes before it returns, inside an outer batch too; `flush()` applies what the current batch has queued so far, and outside a batch does nothing.
- Added: `reaction(compute, apply)` in `@reactre/core/features/reaction`, an effect in two halves, as Solid 2.0's `createEffect(compute, apply)`: `compute` is tracked, and `apply(value, prev)` runs untracked when its value changes, returning a cleanup if it likes. `effect(fn)` is unchanged.
- Changed: these are feature modules, not exports of `@reactre/core`, whose main entry keeps 0.0.3's runtime API (it gains only the compiled-away control flow below), and none hooks into the code that runs without it. An app that does not import them ships the same code as with 0.0.3: the existing size profiles' bundles are the same code, byte for byte, once local names are left unminified, and the same size minified. Their gzipped sizes are 0.0.3's, or a few bytes off, as Bun's minifier picks local names from the letters of the whole source file, code it drops included. `test/features.test.ts` adds three profiles for them: `root`, `settled` and `reaction`.
- Added: `<Show when fallback keyed>`, `<Switch fallback>` with `<Match when keyed>`, `<Repeat count from fallback>`, `<Portal mount>` and `<Dynamic component>`, as Solid 2.0 has them, and a `fallback` on `<For>`, shown while `each` is empty. They are compiled away: an app that uses none of them ships none of them, and one that does ships no runtime of theirs. A `<Show>` rebuilds its children only when `when` turns truthy or falsy (with `keyed`, for every new value), and a function child gets an accessor of the value; a `<Switch>` rebuilds only when another `<Match>` becomes the first truthy one. `test/features.test.ts` adds a `show` profile, an app with a `<Show>`, a `<For>` fallback and a class list.
- Added: `dynamic(source)` in `@reactre/core/features/dynamic`, a component that renders the component or tag name `source` returns. It runs, so it is a feature module; `<Dynamic>` and the types both take (`DynamicComponent`, `PropsOf`) are in `@reactre/core`.
- Added: JSX types for them, and for `class` as an object or an array, `ref` as an array of refs, and `defaultValue`, `defaultChecked`, `defaultSelected` and `defaultMuted`. Each control flow element throws when called, naming the compiler and the import it looks for.
- Added: Solid 2.0's stores in `@reactre/core/features/store`. `createStore(value)` returns a deep reactive proxy, whose reads subscribe to the property read alone (an array's by index and `length`, an object's keys by a signal of their own), and a draft-first setter, `setStore((s) => { s.todos.push(todo) })`, whose writes are batched; an object the setter returns replaces the store's contents shallowly. `createStore(value, { shallow: true })` is a one-layer store, `createStore(fn, seed)` a derived store that can be written, and `createProjection(fn, seed, { key })` a read-only one, into which what `fn` returns is reconciled. `reconcile(value, key)` writes only what differs, keeping objects of the same key ("id", or null for by index); `snapshot` and `deep` return plain copies, `deep` after subscribing to everything; `merge` and `omit` are Solid 2.0's props helpers, whose properties are getters of their sources. In TSX, a store read is reactive where the compiler sees a call, as a signal read is: `{store.count}` is written once, and so is a `<For>` row's hole that reads only its item (`t.done`), since a store's items change in place. `<For>` needs a new array for each render: `each={[...store.todos]}`.
- Added: `memo(fn, { equals })` and `signal(fn)` in `@reactre/core/features/memo`, under core's names, as Solid 2.0's options for them. `memo`'s `fn` is given its last value, `equals` decides whether its readers re-run (`false`: every time), and `signal(fn)` is a writable derived signal: `fn(prev)` recomputes it when its sources change, and a write sets it until then. `signal(value, { equals })` takes the option too. Solid 2.0's `lazy` and `unobserved` are left out: they need a count of a signal's readers, which core's signals do not keep.
- Changed: both are built from `@reactre/core`'s public API, and ship only with their import: the existing size profiles are unchanged. `test/features.test.ts` adds two profiles for them: `store` and `memo`.
- Added: `createContext(default?)` and `useContext(ctx)` in `@reactre/core/features/context`, Solid 2.0's context. A context is a component, `<Ctx value={v}>children</Ctx>`, with no `.Provider`; what its children make finds the value then and later (a slot's next content, a `<For>`'s next row, an effect's next run). `useContext` returns the nearest provider's value, else the default, and throws `ContextNotFoundError` for a context without a default; a provider of `undefined` is no provider.
- Added: `<Errored fallback>` in `@reactre/core/features/errors`, Solid 2.0's error boundary: its children, or the fallback (an element, or `(err, reset) => ...`) once something they made throws while it is built or while it updates (a component's body, an effect's or a slot's run, a `<For>` row). What the children made is disposed; `reset()` builds them again. Beside it, `effect(fn, { error })`, the core's `effect` with a handler for what its runs throw, and `configureClientErrors({ onError })`, which gets what no boundary catches; without either, errors are thrown on as before.
- Changed: nothing for an app that imports neither. A provider and a boundary read `props.children` inside themselves, so they need their children unbuilt; the compiler passes JSX children as a getter (lazy children, below), so `<Ctx value="dark"><Label /></Ctx>` and `<Errored fallback={...}><Child /></Errored>` work as written, and a boundary catches a throw in its child's component body. Both read their children in a slot, so a child that may change (`{more() ? <A /> : null}`) is read again under them. Each module installs itself as it loads, by wrapping methods of the core's owned effect class (and, for errors, of its row observer class, now exported as the internal `__RowObserver`, beside `__Owned`): an app that imports neither ships the same code as before, byte for byte with local names left unminified and the same size minified; gzipped, the benchmark app and `reaction` are 1 byte larger, as Bun names locals by the letters of the whole source. `test/features.test.ts` adds two profiles, `context` and `errors`.
- Changed: props are reactive, as in Solid. A component still runs once; a prop passed an expression that calls a function (`<Label text={name()} />`) updates the holes that read it (`{props.text}`), and children that hold JSX are built when the component reads `props.children`, after its own code before that, so a provider can set up first. Destructured props (`({ text }) =>`) are read once, when the component runs. The types are unchanged: props are typed as values. The README has a Props section.
- Added: `__props`, which merges a component call's spread props keeping their getters, so `<Child {...props} />` passes reactive props on. It is in a bundle only where compiled code calls it. Every existing size profile is unchanged, byte for byte; `test/features.test.ts` adds a `props` profile, an app that passes props reactively, spreads them and builds children lazily.

### @reactre/compiler

- Added: control flow, recognized by its import from `@reactre/core` (under any name, or through `import * as`), so a component of an app's own named `Show` or `Switch` stays a component. `<Show>` and `<Switch>` compile to a slot behind a memo of the condition or of the matched case, `<Repeat>` to a keyed list over the indexes, a `<For>`'s `fallback` to a slot beside the list, `<Portal>` to an insert into its mount undone by `onCleanup`, and `<Dynamic>` to a slot that calls the component or builds the tag's element (a tag written as a string compiles as the element itself). What cannot compile is a compile error: a `<Match>` outside a `<Switch>`, a `<Repeat>` outside an element, a `keyed` that is not written as a boolean, props an element does not take.
- Added: `class` written as an object or an array literal is taken apart while compiling. Classes it can see join the template, an object's other keys become `classList` toggles (bound when they read a signal), and a list with an item it cannot see into is one string through `__class`, imported only by a file that has one. `ref={[a, b]}` gives the element to each ref.
- Fixed: `defaultValue`, `defaultChecked`, `defaultSelected` and `defaultMuted` are set as properties. Before, they were written as attributes of those names, which the browser ignores.
- Changed: nothing else. A file that uses none of these compiles to the same code as in 0.0.3, byte for byte (`test/flow.test.ts` keeps the benchmark app's code and a file of every older construct as snapshots), and the benchmark app's bundle is the same 6,756 bytes gzipped.
- Added: reactive props. A component call passes a prop whose expression calls something, or reads a prop the component around it may be passed reactively, as a getter, and so are props holding JSX (children, mostly), which are then built when read. Literals, plain names and function literals stay values, so a call site of static props compiles as before. Spread props at a component call go through `__props`, which keeps getters.
- Added: in a component, a hole that reads a prop (`{props.title}`, `class={props.cls}`, `<Show when={props.open}>`, a handler) is bound only if some call site may pass that prop reactively, else written once as before. `compileJs(js, { props })` takes those facts; without the option, a file is seen alone, and a component it exports or uses as a value is reactive in every prop. `@reactre/compiler/program` finds the facts for a whole program (`scanModule`, `Program`, `analyze`), and `reactreCompiler()` reads the program from Bun.build's entrypoints (`wholeProgram: false` turns it off). A module that joins late and breaks the facts of one compiled already fails the build.
- Changed: `{props.children}` (or `{children}` from a destructured parameter) in an element is inserted, so children that are nodes render; it was a text hole.
- Fixed: a template literal's substitutions count for the reactivity rule: `{`${count()}`}` follows `count`. Before, the scanner skipped the whole template, and the hole was written once.
- The benchmark app compiles to the same bytes as before, with `compileSource` and through @reactre/plugin's whole-program builds, and so does a variant whose `Button` reads `props.title` rather than destructuring: every call site passes literals. The golden snapshots are unchanged.

### @reactre/plugin

- Added: core mode reads the whole program at a one-shot build's start (`vite build`, Rollup, Rolldown, esbuild, webpack, Rspack, Bun), following each import the bundler's own resolver places among the app's files, so a component's holes that read a prop are bound only where some call site passes that prop reactively. A dev server and watch mode, and a build whose graph cannot be seen (`import(expr)`, `import.meta.glob`, a virtual module, webpack's function entries), compile each file alone. The `wholeProgram` option (default true) turns it off.

## [0.0.3] - 2026-11-01

### Every package

- Changed: each export's `types` condition names a declaration file in `dist/` (`dist/index.d.ts`, `dist/features/*.d.ts`, ...), written by the build, not the TypeScript source. A project that imports reactre type-checks its declarations under its own settings, `skipLibCheck: false` included, with `moduleResolution` `bundler`, `node16` or `nodenext`; before, its compiler read reactre's sources and failed on their `.ts` imports unless it set `allowImportingTsExtensions`. Bun still runs the sources, through the `bun` condition.

### @reactre/dom

- Added: `Prototype`, the part of `Template` that clones: parsing, `clone`, `locate`, `locator` and `write`, without `mount`, blocks or the check of hole markers against their positions. `Template` extends it and is unchanged. @reactre/core's compiled templates use it, so an app built with reactre's compiler ships neither `Block` nor the checks (about 0.4 KB gzipped).

### @reactre/core

- Added: JSX types for reactre's TSX. With `"jsxImportSource": "@reactre/core"`, TypeScript checks every HTML and SVG element's attributes, `on*` handlers by their event's type, children, and `<For>`'s rows by the type of `each`. `style` takes a string or an object of CSS properties, and `ref` a function or an object typed by the element. What the compiler cannot compile is a type error: a function as an attribute or a child, a capture handler, children of a void element.
- Added: `@reactre/core/jsx-runtime` and `@reactre/core/jsx-dev-runtime`, where TypeScript finds those types. Their `jsx` functions throw, naming the compiler: compiled TSX never calls them.
- Added: `onCleanup(fn)`. Each effect run owns the effects and cleanups it makes, and disposes them before it runs again. A slot that replaces its content (`{cond() ? <A /> : <B />}`) now stops the old content's effects; before, they stayed subscribed and wrote to detached nodes.
- Added: `attach(view, parent)`, `render` returning a function that removes the view and stops its effects. `render` itself returns nothing, as in 0.0.2.
- Added: a `<For>` row can hold components, nested `<For>` lists and JSX expressions. They belong to the row: a new item for the row's key builds them again, and they are disposed when the row leaves. Before, these were compile errors.
- Fixed: a `<For>` row that reads two selectors, or one selector with two keys, follows all of them, with `@reactre/core/features/selectors`, which @reactre/compiler imports for a row whose reactive holes make two or more calls with arguments. Without the module, the row's second key throws an error naming it. Before, the row followed only the last key it read.
- Fixed: an effect outside a list that stops asking a selector about a key no longer re-runs when that key gains or loses the selection.
- Fixed: a batch that queues many effects takes time linear in their number; before, queueing searched the queue each time.
- Changed: an effect that writes a signal it reads runs again after its run ends instead of inside it, and throws after 100 runs in a row. Before, it recursed until the stack overflowed.
- Fixed: a `<For>` row's `onFocus`, `onBlur` and other handlers for events that do not bubble are called. The list's listener for them now listens in the capture phase, as the compiler marks them.
- Changed: an app ships only the runtime it uses. Ownership (`onCleanup`'s owners, slots that dispose their content, rows that hold components, `attach`) comes with `effect`, `memo`, a slot, a fragment, a row with components, lists or slots, or `attach`; an app with none of them leaves it out, as it has nothing to dispose. The js-framework-benchmark app's bundle is 6,726 bytes gzipped, from 7,773 before and 6,871 in 0.0.2; the whole package, every feature in, is 7,008. `test/features.test.ts` checks each profile against `sizes.json`.

### @reactre/compiler

- Added: fragments, spread props, `style` as an object or a string, `ref` (a function, or an object given the element as `current`), and `key` on an element outside `<For>`, which rebuilds the element when a key that calls something changes. Fragments and spread props were compile errors before, and so was such a key.
- Fixed: an SVG element at the root of a template (a component that returns `<g>` or `<circle>`) gets the SVG namespace, and `class` inside SVG is set as an attribute.
- Fixed: `value`, `checked` and `selected` that are not literals are set as properties, so they show the state after the user has typed or clicked.
- Fixed: a handler outside a list whose expression reads a signal (`onClick={editing() ? save : edit}`) follows it. Before, it was bound once. A function literal is still bound once.
- Changed: a file that uses none of these compiles to the same code as before, except that a `<For>` row's handler for an event that does not bubble is marked for the capture phase, and a row that makes two or more calls with arguments in its reactive holes imports `@reactre/core/features/selectors`.
- Added: `compileJsWithMap`, `compileJs` with a version 3 source map back to its input, and `@reactre/compiler/map`, which @reactre/compat/compiler shares. The code is `compileJs`'s, byte for byte.

### @reactre/full-compat

- Added: a new package, @reactre/compat with React's time slicing. (npm also has a 0.0.2 of it, published after v0.0.2 was tagged; 0.0.3 is its first release with the other packages.) A transition's render yields to the page every 5 ms: events, timers and paints run between slices, an urgent update made meanwhile commits first and the transition renders again from the start, and one that has waited 5 seconds renders the rest at once, as React's concurrent render does. Between slices the render is undone, so the page shows the last commit. The check before each component costs on every render, so only this package's builds compile it in. About 1 KB gzipped more than @reactre/compat. Its development build (`dist/dev`, the `development` export condition) has Fast Refresh, as @reactre/compat's does.

### @reactre/compat

- Added: `compileJsWithMap` in @reactre/compat/compiler, `compileJs` with a version 3 source map back to its input. The code is `compileJs`'s, byte for byte.
- Added: Fast Refresh, in a development build of the client and server entries (`dist/dev`) that the `development` export condition resolves, as Vite's dev server does. Its first root registers the renderer with react-refresh through `__REACT_DEVTOOLS_GLOBAL_HOOK__`, as `react-dom`'s development build does, so @vitejs/plugin-react's Fast Refresh works: an edited component renders again in place with its new code, keeping its state, and its effects and memos run again; a component whose hooks changed, and a class component, mount anew; a root an error emptied renders again once an edit fixes it. A compiled template keeps its DOM over an edit that leaves its markup as it was. The production builds strip the Fast Refresh code from core.ts as they strip time slicing, so their dist, sizes and speed are as before, byte for byte.
- Added: `@reactre/compat/features/timeSlicing`, which turns time slicing on where the build compiles it in (@reactre/full-compat's). @reactre/compat's own builds strip the slicing code from core.ts before they compile it, so its dist, sizes and speed are as before, byte for byte.
- Fixed: @reactre/compat/compiler passes a list row's loop the names its body spreads. Its free-name scan took a name after `...` for a property, so `rows.map((r) => <li {...extra}>{r}</li>)` threw a ReferenceError for `extra`, or read a module-level `extra` instead; the same held for spreads into objects, arrays and call arguments. An element with a spread child (`<li>{...xs}</li>`) now stays a jsx call: its template had one hole for any number of children and rendered only the first.
- Fixed: a class's legacy will-method and its `UNSAFE_` twin both run, the plain one first, as React calls them (`componentWillMount`, `componentWillReceiveProps` and `componentWillUpdate`). Before, the `UNSAFE_` one ran alone.

### @reactre/plugin

- Added: source maps. A compiled file's map leads back to the `.tsx` or `.jsx` you wrote, through oxc's map, the rename of oxc's helpers and the compiler's own, so a runtime error's stack maps to its line and column. Vite, Rollup, Rolldown, esbuild, webpack and Rspack take it when their own source map option is on, and `vite dev` serves it inline; the plugin builds none when the bundler asks for none. Bun's plugins cannot return a map, so `Bun.build` maps a bundle to the compiled code. The compiled code is the same as before, byte for byte. Before, a compiled file had no map.
- Added: compat mode works with @vitejs/plugin-react's Fast Refresh (`plugins: [reactre({ compat: true }), react()]`): in `vite dev`, `react` resolves to compat's development build, which registers with React Refresh. The docs now set the plugin up with it.
- Added: `compat.package`, `"@reactre/compat"` (the default) or `"@reactre/full-compat"`: the package `react`, `react-dom` and their server entries resolve to, and the module written for the options builds on.

## [0.0.2] - 2026-10-30

### @reactre/core

- Fixed: a `<For>` row with several handlers for one event type, such as two `onClick` links, calls the clicked one once per event. Before, the list added one listener per handler, so each click ran the handler once per handler of its type.

### @reactre/plugin

- Added: the behaviour key `renderUndo`, on unless `compat.exclude` names it: the module written for the options loads `@reactre/compat/features/undo`, React's handling of an update outside a transition that suspends with no Suspense boundary above (the screen stays as it was until the data comes).
- Added: the behaviour key `viewTransitions`, on unless `compat.exclude` names it or `concurrentRendering` is off: the module written for the options loads `@reactre/compat/features/viewTransitions`, React's view transitions.
- Added: the behaviour key `concurrentRendering`, on unless `compat.exclude` names it: the module written for the options loads `@reactre/compat/features/concurrent`, React's transition lanes.
- Added: the behaviour key `renderRetry`, on unless `compat.exclude` names it: the module written for the options loads `@reactre/compat/features/retry`, React's retry of a render that throws.
- Changed: with anything switched off, class support included, `react` resolves to a module built on @reactre/compat/core that loads the feature module of each key still on (`@reactre/compat/features/classes`, `/stacks` and `/keys`). `classes: false` now keeps component stacks and React's handling of repeated keys; before, it resolved to @reactre/compat/core, which dropped both. Only the default options resolve to @reactre/compat itself.
- Added: `compat.exclude` takes the behaviour keys `componentStack` and `repeatedKeys`, which are on unless excluded, whatever `compat.apis` lists.
- Added: `compat.apis` and `compat.exclude` switch React's APIs on and off one by one, by export name or group (`@suspense`, `@transitions`, `@forms`, `@hints`, `@classes`). With any off, `react` resolves to a module written for the options, which imports only the APIs that are on and exports each one that is off as a function that throws, naming the fix. The build fails where a module, a dependency included, imports a switched-off API, reads it as `React.x`, or takes it from `require("react")`.
- Changed: in compat mode, `classes` defaults to true: `react` resolves to @reactre/compat, React's whole client API. `classes: false` resolves it to @reactre/compat/core, without class components.
- Changed: in compat mode, `react-dom/server` and `react-dom/static` resolve to @reactre/compat/server and @reactre/compat/static, whose export conditions pick the build as `react-dom`'s do: a bundle for the browser or a web worker gets compat's browser entry, which throws React's minified error codes as React's browser build does, and a Node SSR build its Node entry. `.browser` resolves to @reactre/compat/server.browser, `.edge` and `.bun` to /server.edge, and `.node` to /server.node, whatever the target.
- Added: in compat mode, `react-dom/server`, `react-dom/static` and their `.browser`, `.edge`, `.node` and `.bun` builds resolve to @reactre/compat/server, with or without `classes`.
- Added: Server Components stay on React: compat mode leaves a Vite environment named `rsc`, and a build that resolves with the `react-server` condition (Vite, Rolldown, esbuild, webpack, Rspack, Bun), alone. In Vite the redirect is now a resolve hook per environment, applied in each environment's dependency optimizer too, instead of `resolve.alias`.
- Fixed: in compat mode, a dependency that cannot see @reactre/compat through `node_modules`, as with Bun's and pnpm's isolated installs, gets the app's copy of compat for `react`, not React or nothing. In every bundler the target resolves from the importer's directory when it reaches @reactre/compat, else from the app's root, else from the plugin's own. `vite dev` now prebundles one copy of compat that the app and its dependencies share; before, its dependency scan failed.
- Added: one plugin for Vite, Rollup, Rolldown, esbuild, webpack, Rspack and Bun, built on unplugin and running under Node and Bun. By default it compiles reactre TSX; with `compat`, it resolves `react` and `react-dom` to @reactre/compat (or its class build) and compiles the app's JSX with @reactre/compat/compiler.

### @reactre/compiler

- Added: an ES module build in `dist/`, so Node can load `compileJs` and the scanner.
- Changed: numbers written as `.5` or `1e3` in JSX are static values, as `0.5` and `1000` are.

### @reactre/compat

- Fixed: a class's `getSnapshotBeforeUpdate` is called as React calls it: after the whole render, children first, with the DOM as it was before the render. Compat writes the DOM as it renders, so where the DOM is watched (`@reactre/compat/features/undo` for urgent renders, a transition's own watch) it undoes the render's DOM changes around the calls and makes them again after. Without a `MutationObserver` it is called before its class renders, as before.
- Fixed: with `@reactre/compat/features/concurrent`, transitions waiting at once render in the order of React's lanes: an event's transitions take the next of React's 10 transition lanes, in a cycle the page shares (an async action's keep its lane), and the ready one with the lowest lane renders first, deferred values' after them and reveals' last. Compat rendered them in the order they started.
- Fixed: with `@reactre/compat/features/concurrent`, a transition whose update suspends in a component rendering on its own, under a Suspense boundary that shows content, waits for the data, as React keeps the screen; compat committed at once and lost the update.
- Fixed: after a render error passes through a Suspense boundary or Activity, `root.render`'s retry renders the component that threw again, so a second throw counts (uncaught, the root emptied, as in React); compat reported it as recovered and kept the old DOM.
- Fixed: component stacks are built as often as React builds them on hydration's renders on the client (the root's and a boundary's), and for the first mismatch at a root; React calls the components on the path to build each.
- Added: `@reactre/compat/features/undo` (the behaviour key `renderUndo`), loaded by `@reactre/compat`: an update outside a transition that suspends with no Suspense boundary above keeps the screen as it was, undone and rendered again once the data comes, as React does; an update's retry after a render error renders the whole batch again, from the component whose update it is, as React's retry does.
- Fixed: an update renders again after any render-phase error, as React's retry does: an error from a child's type, a context consumer, `lazy` or a class lifecycle too, not only one a component's own render threw.
- Fixed: the retry of a render that threw computes again the `useMemo` values the failed render computed, as React renders again from the committed hooks.
- Fixed: with `@reactre/compat/features/concurrent`, an update to one root, or a commit that reaches it, wakes only the transitions waiting on that root, as React clears only that root's suspended lanes; compat woke them on every root.
- Fixed: with `@reactre/compat/features/concurrent`, an urgent update that sets state to the value it has, while a transition waits to change it, renders the component, which then bails out, as React does; compat rendered nothing.
- Fixed: an update that gives a void element (`<input>`, `<img>` and the like) children that render no node throws React's #137, as on mount.

  - Showing runs each effect once, children first, and attaches the refs and calls `componentDidMount` again.
  - An Activity inside hidden content waits for that content.
  - Shown content that suspends again has its layout effects and refs cleaned up until it is revealed, and its passive effects stay connected.
- Fixed: `unstable_batchedUpdates` is `fn(a)`, as React 19's is: updates outside an event render when the scheduler runs them.
- Fixed: a transition callback that throws synchronously sends the error to the component's error boundary (`useTransition`), or reports it (`startTransition`), instead of throwing to the caller.
- Fixed: a class's ref is detached before its `componentWillUnmount` runs, and either can throw without stopping the other. A callback ref to a class instance may return a cleanup, which runs instead of a call with `null`.
- Fixed: an element made by React 18 or older (`react.element`) is not a valid element and throws React 19's error when rendered. React's messages and hints are used for an invalid element type, and an object of another class rendered as a child is named by its tag, such as `[object Date]`.
- Fixed: events follow react-dom's rules:
  - `onChangeCapture` runs in the bubble phase with `onChange`, after the other bubble handlers.
  - `onChange` fires only for text fields (React's list of input types), checkboxes, radios, selects, file inputs and custom elements. A `change` event on a text field fires it when the value moved.
  - A non-bubbling event such as `load` runs the handlers of every element up the tree, and its capture handlers run in the capture phase. Elements React listens on, such as an `<img>`, need no handler of their own for that.
  - The far end of an enter or leave event from outside the root is the window.
  - `isDefaultPrevented()` is true after `preventDefault()`, even for an event that cannot be canceled.
- Fixed: the resource hints follow react-dom's rules:
  - `preconnect` keys on `crossOrigin` too.
  - `preload` needs an `as`, always fetches fonts with CORS, and passes `integrity`, `nonce`, `referrerPolicy`, `imageSrcSet`, `imageSizes` and `media` on.
  - `preinit` needs `as: "style"` or `as: "script"`. A stylesheet gets `data-precedence` and goes after the last one of its precedence.
  - `preinitModule`'s script is async.
  - A stylesheet or script takes what it lacks from an earlier preload of it.
  - Without a document, every hint does nothing.
- Fixed: element props follow React 19's rules:
  - Boolean attributes use React's list by prop name, `credentialless` included, and are present for any truthy value.
  - `muted`, `multiple` and an `<option>`'s `selected` are set as properties only.
  - An empty `src`, or an empty `href` off an `<a>`, is left out.
  - `cols`, `rows`, `size` and `span` need a number of at least 1, and `rowSpan` and `start` need a number.
  - `innerText` and `textContent` props are ignored.
  - `xlink*` and `xml*` props are namespaced on every element.
  - A `javascript:` URL in `src`, `href`, `action`, `formAction` or `xlinkHref` is replaced by one that throws, as React blocks it.
  - A custom element takes any value through a property it defines, strings and `undefined` included.
  - A custom element's own `on*` function props, such as `onMyEvent`, are native listeners for the event named after "on"; React's event props stay synthetic.
  - A prop starting with "on", in any case, is never an attribute of a built-in element.
- Fixed: styles follow React 19's rules: a string `style` throws, React's own list decides which numbers get `px`, and string values are trimmed.
- Fixed: form fields follow React 19's rules:
  - A boolean `value` is written as text.
  - An uncontrolled `<textarea>`'s `defaultValue` updates its default.
  - A controlled `<textarea>` with a `defaultValue` keeps it as its default.
  - A `<select>` with no matching option selects its first enabled one.
  - A `<select>`'s `defaultValue` also sets its options' `defaultSelected`.
  - A change of `multiple` with no `value` applies the `defaultValue` again or clears the selection.
- Changed: an update made outside React's event handlers renders as React's lanes order it: in a microtask during a discrete event such as a click or a key, and otherwise (timers, promises, continuous events such as mouseover) in a task of its own, so updates from timers that fire one after another render together (react-tooltip moving between anchors).
- Added: an ES module build of `@reactre/compat/compiler` in `dist/`, so Node can load `compileJs`.
- Docs: setting up Vite, with @reactre/plugin or an alias.

### @reactre/preact

- Added: first release. Preact 11.1.0's API and behaviour, its renderer, hooks and compat layer ported, on reactre's templates: `@reactre/preact/core` stands in for `preact` and `preact/hooks`, `/compat` for `preact/compat` and `react`, and `/jsx-runtime` for the JSX runtimes. `/compiler` (a Bun plugin) and `/plugin` (Vite, Rollup, Rolldown, esbuild, webpack and Rspack, under Node and Bun) compile JSX element trees into templates, and their `off` option switches APIs off one by one or by group, such as `@classes`; the build fails where a module uses a switched-off API, or reads the module in a way it cannot follow. `html` writes templates in plain JavaScript with no build step, and `/dom` is the DOM-only build: templates and events, no components.

## [0.0.1] - 2026-10-29

First release.

### @reactre/dom

- Templates parsed once and cloned, with typed holes for text, classes, attributes, properties, events and slots.
- A keyed `List` that reuses rows and makes the fewest DOM moves, and `morph`.

### @reactre/core

- Signals, effects, `memo`, `batch`, `untrack` and a keyed `selector`.
- `<For>` keyed lists and `render` for TSX views compiled by @reactre/compiler, on @reactre/dom's templates.

### @reactre/compiler

- A Bun plugin that compiles reactre TSX into templates and the code that updates them.

### @reactre/compat

- React 19's client API on @reactre/dom's templates: hooks, context, memo, refs, portals, Suspense and lazy, transitions, synthetic events, controlled fields and hydration.
- `@reactre/compat/classes` for class components, and `@reactre/compat/compiler`, a Bun plugin that compiles host JSX trees to templates.

All packages ship ES modules for browsers and bundlers, and TypeScript sources for types.

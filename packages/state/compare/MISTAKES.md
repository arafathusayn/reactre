# @reactre/state: the catalog of mistakes

Written 2026-11-10. This is V4's section 2 ([`../V4.md`](../V4.md)): one list of the mistakes an agent makes writing a machine in this library's API. It merges two research reports, the flat catalog in [`README.md`](README.md) section 1 (`C#1`–`C#40`), the evidence table in [`../README.md`](../README.md) (`R#1`–`R#65`), and every case in [`../test/mistakes.ts`](../test/mistakes.ts), [`../test/features/*/mistakes.ts`](../test/features), [`../test/compiler.test.ts`](../test/compiler.test.ts) and [`../test/features/*/compiler.ts`](../test/features). Each row is one mistake, deduplicated across all of them.

## What counts

A row counts toward V4's bar of 200 only when a test pins it:

- a `@ts-expect-error` case in a `mistakes.ts` (`bun check` fails if it stops being an error), or an `expect<Equal<…>>()` that pins the exact message (it fails too when the error goes away);
- or a compiler case in `test/compiler.test.ts` or a feature's `compiler.ts`.

Each `pinned:` status names the file and the line of the case (or the group and name of a compiler case). It was found by reading the file, not taken from the reports. `compare/mistakes.ts` is a comparison script, not a test, so it pins nothing.

Two kinds of pinned rows don't count:

- `pinned (runtime):` a runtime test pins the behaviour (a `StateError` code, or a `send` result). V4's bar is mistakes caught before the program runs.
- `pinned (restriction):` the last group. The compiler refuses code that is correct (a rest element, a spread in setup's `states`), so that it can compile the machine. A refusal of correct code isn't a mistake caught.

The other statuses:

- `caught, not pinned`: `bun check` or the compiler reports it today, checked by writing the mistake in [`out/mistakes-scratch/`](out/mistakes-scratch) (`types.ts` with `marks.ts`, and `compiler.ts`; the folder is gitignored). It needs only a case.
- `to do: type`, `to do: build`, `to do: runtime-dev`: no layer reports it; the row says the rule that would. Checked in the scratch folder where the row says so.
- `impossible:` the API can't express it, and why.
- `not caught:` a logic or policy bug that no checker can see, said plainly.

Catch kinds: `type` (`bun check`), `build` (the compiler, run by the bundler plugin), `runtime-dev` (a `StateError` or a development-build warning), `impossible`, and `none`.

One row per mistake. Variants of one mistake (the clock read in `on`, in `always`, in a `choice`) are one row, with every pin listed. Where a research row is the same mistake as a `C#`/`R#` row, it is listed in the same row.

- **A shape changed, its version kept** (the owner's decision: "a hash in setup"): M260. A setup whose `use` lists persist or durable keeps `shape: "<hash>"`, the hash of its version and the contracts written in setup; a missing or stale hash fails the build with the next version's hash and the migration to add.

M77 refuses body reads with no failure-path status check on their own promise path. Logging `res.status`, or checking it only in an unrelated deferred callback, leaves a 4xx/5xx response accepted and is refused. `if (!res.ok) throw`, ternaries in `.then`, and checks that preserve successful non-200 statuses such as 201/204 pass. test/fetcher.ts and the README's first example now check `res.ok` and throw, so the task's `error` decides.

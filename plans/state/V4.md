# @reactre/state v4: the best TypeScript state machine library, by measurement

Written 2026-11-10 17:50 +06. It follows the user's decisions recorded in [`PARITY.md`](PARITY.md)'s status block, and keeps [`SPEC.md`](SPEC.md)'s rules: Bun and TS only, the Write and Edit tools only, two layers that never overlap, and every message is the fix.

## The goal

The user asked for these, in their words:

- "Limit is 1.5 KB. We need more speed, type-safety, compiler enforced safety. 200+ AI agent mistakes should be caught. Research web properly."
- "beat all state machines libraries in TypeScript in ergonomics, safety, and in speed", using a JS engine profiler (Bun's, V8's) to find hot paths.
- Move it to `packages/state`, under CI's 100% coverage.
- Keep the one-file rule for a machine's shape (S4).
- The compiler checks functions a transition calls: same-file functions with the same purity rules, imports only from modules marked pure.

## The rivals

Installed as devDependencies (nothing ships): XState v6 beta (with `xstate/fsm`) and v5, robot3, @zag-js/core, @xstate/store, typescript-fsm, yay-machine, @doeixd/machine, @stateforward/hsm, @escapace/fsm, jssm. Each gets a door port, and a job port where it has tasks and timers.

## The work

### 1. Speed (profiles first)

The production profile of a send is the handler, `__flat` and `__snap`, with three allocations a step: the handler's `[state, data]`, the snapshot, and the result. Done: index access in `__snap`, two direct calls in the step, no listener round without listeners, listeners isolated from each other's throws. Next, each kept only if `compare/bench.ts` shows it faster and nothing slower:

1. A compiled `to()` returns the snapshot itself (one allocation fewer, no tuple): every reader of `step[0..2]` changes, in every feature.
2. One shared frozen empty data object for states with no data.
3. Listeners in a copy-on-write array instead of a Set.
4. V8 profiles too: each bundle in headless Chrome through `apps/profiling`'s puppeteer-core, since apps run in browsers.

### 2. The catalog of mistakes

`compare/MISTAKES.md` merges the two research reports (`X1`–`X182`: XState and statecharts, from Stately's docs, about 55 issues and 19 discussions, and the agents' guides; `L1`–`L107`: what LLM agents get wrong in TypeScript, from papers and teams' reports). Each row: the mistake as code in our API, its source, how it is caught (type, build, runtime, or impossible to write), and the test that pins it. Only a pinned row counts toward 200.

### 3. The type layer

The cheap cases first (each one `@ts-expect-error` line), then the new rules:

- **A use site can't hide a broken machine:** `createActor`, `useActor`, `transition`, `restoreActor` and `initial` refuse an `any` machine and an `any` snapshot.
- **A task's result is a boundary:** no `any` in the event a `run` resolves to.
- The rest come from the catalog (X2, X17, X47, X50, X51, X78, X83, X96, X100, X101, X124, X132, X134, X143, X156, and the L rows marked type).

### 4. The compiler

- **Calls in transitions** (the user's decision 5): a same-file function a transition calls is checked by the same purity rules, transitively. An imported one must come from a module marked pure. How a module is marked is part of this step.
- **Use sites:** no `@ts-` suppression, cast or `!` on a line that passes a machine, in any file the build compiles.
- **`run` hygiene:** a `fetch` not given the `signal`; a catch that resolves to a success event; `forEach(async`; `throw` of a non-Error; `setInterval`, `WebSocket` or `addEventListener` in `run` without cleanup; casts in the object `run` returns.
- From the catalog: X20, X26, X41, X45, X46, X109, X138, X150, X158, X178–X180.
- S4 (a shape from another file) becomes a build error too, where the compiler can see the import.

### 5. Runtime, development only

A send to a stopped actor, a send no state handles, listener loops, `useActor` input changing between renders: warnings in the development build only, so production ships none of their bytes.

### 6. The move to `packages/state`

After the rivals' ports land (they are being written in `compare/` now). `plans/state` becomes `packages/state`: the root workspaces, the tsconfigs, the CI build and pack loop, `scripts/consumer.ts`, and every coverage gap closed (the codemod, `entries/serialize.ts`, `entries/scxml.ts`, `system/pure.ts` and about 20 smaller ones) so `bun test --coverage` stays at 100%.

## Open, and decided

- **A shape changed but its version kept** (decided by the user, 2026-11-10: "a hash in setup"): a persisted machine's setup has `shape: "<hash>"`, a hash of its version and contracts the compiler computes; a mismatch fails the build with the fix (bump the version and add a migration, or set the new hash). Required where `use` lists persist or durable (the lead's call: only saved snapshots need it).
- **The pure-module mark** (the compiler agent's call): a file's first statement `"use pure";`, or a package in the plugin's `pure` option; a marked file's functions are held to a transition's rules.

- **Listeners in an array** (decided by the user, 2026-11-10): a function subscribed twice is told twice, and one unsubscribe removes both. A duplicate check would cost about 10% of create.
- **The shared empty data, `__none`, stays frozen in every build** (decided by the user, 2026-11-10): 13 bytes, so untyped code can't change every actor's empty data.

- **A move to the same state, in a state with a task or timer** (decided by the user, 2026-11-10): a type error. Now the task and timers keep running with the data they started with, so a typeahead written as `to("loading", { q: event.q })` inside `loading` gets the old query's result. The error says to choose: `reenter` restarts the task and timers with the new data, and an explicit keep leaves them running. The agent must choose, so the race can't happen by accident.
- **@zag-js/core** isn't benchmarked: it only defines machines, and the code that runs one is in its framework packages (`@zag-js/vanilla` and the others). Add `@zag-js/vanilla` to measure it.
- Seven runtime behaviours the research couldn't confirm (X20, X24, X93, X104, X131, X136, X141) are checked by tests before any doc claims them.
